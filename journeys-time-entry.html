Journeys Time Entry

Enter your weekly Nextiva Journeys time from one timesheet grid, with one row per activity and one column per day. It opens in Chrome's side panel, shows your billable and capacity percentages, and keeps your Burn Down Record sheet in step with Journeys.

Install or update with the installer (Windows)

  1. Option A: press Win+R, paste this line, and press Enter: 
    powershell -NoProfile -ExecutionPolicy Bypass -Command "$x='journeys-time-entry'; irm https://jasonkbarry.github.io/extensions/install.txt | iex"

    Option B: download Install-JourneysTimeEntry.zip, right-click it and choose Extract All, then double-click the .cmd file inside. If Windows warns you, click More info → Run anyway.
  2. First time: it installs to %LOCALAPPDATA%\Nextiva Extensions\journeys-time-entry, copies that path to your clipboard, and opens chrome://extensions. Turn on Developer mode and click Load unpacked. In the folder window, click the address bar, press Ctrl+V then Enter, and click Select Folder. Pin Journeys Time Entry from the puzzle-piece menu.
  3. Updates: run it again (either option). It finds where the extension is installed in any Chrome or Edge profile, even a folder you chose yourself, and copies the new version there. Your boards and settings are kept, and the extension reloads itself within about a minute.

A blue bar in the panel tells you when a new version is out, and ⚙ → Check for updates checks right away. Updating from 2.5 or earlier? After the installer runs, click the extension's reload arrow in chrome://extensions once. From 2.6 on, it reloads itself. Requires Chrome or Edge 116 or newer, and you must be signed in to onboarding.nextiva.com.

Install manually

  1. Download the zip and extract it. Move the journeys-time-entry folder somewhere it can stay; Chrome keeps loading it from there.
  2. Go to chrome://extensions, turn on Developer mode, click Load unpacked, and choose the folder.
  3. Pin Journeys Time Entry. Clicking it opens the extension in the side panel, which stays open while you switch tabs.

Set up your customers

  1. In Journeys, open a customer's post-onboarding board and copy the URL from the address bar (…/accounts/…/projects/…/post-onboarding).
  2. In the extension, click ⚙, paste the URL under Add a board, and click Add. The customer name fills in automatically.
  3. Click Activities: 0 selected ▸ and tick the cards you log time to. Cards from any column can be picked, and none are ticked by default.

Admin categories come from your pinned rows on the Journeys Timesheet page.

Use

  • Choose Project and a customer, or Admin, then type hours in the grid. Use ‹ › to change weeks.
  • Billable entries that have no matching Burn Down row show in orange once the sheet is connected. Use Sync to fix them.
  • Your existing entries show in green. New or changed cells show in blue. Clearing a green cell marks it red, to be deleted.
  • Submit sends only the changes: it creates new entries, updates changed hours, and deletes cleared entries after asking you to confirm.
  • Each row has a comment box and a BILLABLE / NON-BILL toggle, both for new entries. Project time is always category Technical. Admin time is always non-billable.
  • Cells with more than one entry show a number badge and are read-only; edit those in Journeys.
  • The header shows, for the week on screen: hours logged, billable % (billable ÷ hours logged, not counting FTO/holiday) and capacity % (billable ÷ expected). Expected is 6.4 h per business day up to today (32 h for a full week), minus FTO/holiday hours up to today. For example, on a Tuesday with 4 h of FTO, expected is 8.8 h. Hover over the header to see the math.
  • A reminder appears every Wednesday at 4 PM, because time is due at 7 PM.
  • Drag the side panel's left edge to make it wider. When it's narrow, the grid scrolls sideways.

Optional: Burn Down Record sheet

For every billable entry the extension creates, it can add a row to your tab in the Burn Down Record, on the first row with an empty Customer Name. It writes through a small Google Apps Script web app that you create under your own Google account.

ColumnWritten value
BCustomer name (set per customer in ⚙)
CCustomer account number
D / EDate and hours of the entry
GCSP level (Standard / Advanced / Signature - TAM)
H / IAllotted hours, bucket of hours
A, F, J–MNot touched. Burn Down ID, Total and the other formula columns stay as they are.

Create the web app (one time)

  1. Go to script.google.com, signed in with the account that can edit the Burn Down Record, and click New project.
  2. Press Ctrl+A and Delete to remove the starter myFunction code, so the editor is completely empty. Paste in all of BurnDown.gs and save. You don't need to edit the script.
  3. Click Deploy → New deployment. Click the gear icon, choose Web app, and set Execute as: Me and Who has access: Only myself. Click Deploy, then Authorize access. If you see "Google hasn't verified this app", click Advanced → Go to (project), then Allow.
  4. Copy the Web app URL, which ends in /exec. It's also under Deploy → Manage deployments. Open it once in Chrome. You should see {"ok":false,"error":"No sheet set…"}, which means the web app is working.

Connect the extension

  1. Click ⚙ and go to Burn Down sheet. Paste the Burn Down Record's address into Sheet link, and the /exec URL into Web app URL. Enter your Tab name exactly as it appears in the sheet. Click Save & test.
  2. For each customer, fill in Sheet customer name, Account #, CSP level, Allotted and Bucket. Billable time is blocked until the customer name, account number and CSP level are set.

If a sheet write fails, your Journeys entries are still saved, and the change waits in a Retry now bar. A row is never written without a valid date.

Deletes and changes

  • Deleting a billable entry from the grid also sets the matching Burn Down row's hours (same customer, date and hours) to 0. The row is kept, not deleted.
  • Changing hours in the grid updates Journeys only. Use Sync to change both at once.

Sync

In Project mode, choose a customer and click Sync. It shows that customer's billable Journeys entries (J) and Burn Down rows (B) grouped by day, with each day's totals for both, and matches entries within each day by hours. Use ‹ › to move between weeks.

LineWhat you can do
J + B (matched)Change the hours and click Save to update both. Delete removes the Journeys entry and sets the Burn Down hours to 0.
J only+BurnDown adds it to the sheet. Change the hours and click Save to update Journeys. Delete removes it from Journeys.
B onlyPick an activity, add a comment, then +Journey logs it in Journeys as billable. Change the hours and click Save to update the sheet. Delete sets that row's hours to 0.

Every Delete needs a second click, on Confirm. Rows set to 0 h are ignored by Sync. Burn Down rows dated in the future can't be added to Journeys; fix those in the sheet.

Changing the script later

Paste the new code and save. Then go to Deploy → Manage deployments → ✏ → Version: New version → Deploy. That keeps the same /exec URL, so nothing changes in the extension. A New deployment would create a new URL, which you'd have to paste into ⚙ again. Optional: set TOKEN in the script, redeploy, and enter the same value in the extension's Token field.

Updating

Run the installer again (Win+R command or the zip). To update by hand instead, copy the new zip's files over your journeys-time-entry folder, keeping the folder name, and click the reload arrow in chrome://extensions. Full documentation is in README.html inside the folder.

Coming from 1.8 or earlier? Also update the Apps Script: paste in the new BurnDown.gs (version 5), save, and use Manage deployments → ✏ → Version: New version → Deploy. Your /exec URL stays the same. If you were on 1.7 or earlier, also fill in Sheet link in ⚙.
