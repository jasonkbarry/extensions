Journeys Time Entry

Enter your weekly Nextiva Journeys time from one timesheet grid, with one row per activity and one column per day. You can also copy billable entries to the Burn Down Record sheet.

journeys-time-entry-1.8.zip · 40 KB
Download Apps Script (BurnDown.gs)

Install

  1. Download the zip, then right-click it and choose Extract All. Move the extracted journeys-time-entry folder somewhere it can stay, such as Documents. Chrome keeps loading it from there.
  2. In Chrome, go to chrome://extensions and turn on Developer mode (top right).
  3. Click Load unpacked and choose the journeys-time-entry folder.
  4. Pin Journeys Time Entry from the puzzle-piece menu. Make sure you're signed in to onboarding.nextiva.com in Chrome.

Set up your customers

  1. In Journeys, open a customer's post-onboarding board and copy the URL from the address bar (…/accounts/…/projects/…/post-onboarding).
  2. In the extension, click ⚙, paste the URL under Add a board, and click Add. The customer name fills in automatically.
  3. Click Activities: 0 selected ▸ and tick the cards you log time to. Cards from any column can be picked, and none are ticked by default.

Admin categories come from your pinned rows on the Journeys Timesheet page.

Use

  • Choose Project and a customer, or Admin, then type hours in the grid. Use ‹ › to change weeks.
  • Your existing entries show in green. New or changed cells show in blue. Clearing a green cell marks it red, to be deleted.
  • Submit sends only the changes: it creates new entries, updates changed hours, and deletes cleared entries after asking you to confirm.
  • Each row has a comment box and a BILLABLE / NON-BILL toggle, both for new entries. Project time is always category Technical. Admin time is always non-billable.
  • Cells with more than one entry show a number badge and are read-only; edit those in Journeys.
  • A reminder appears every Wednesday at 4 PM, because time is due at 7 PM.

Optional: Burn Down Record sheet

For every billable entry the extension creates, it can add a row to your tab in the Burn Down Record, on the first row with an empty Customer Name. It writes through a small Google Apps Script web app that you create under your own Google account.

ColumnWritten value
BCustomer name (set per customer in ⚙)
CCustomer account number
D / EDate and hours of the entry
GCSP level (Standard / Advanced / Signature - TAM)
H / IAllotted hours, bucket of hours
A, F, J–MNot touched. Burn Down ID, Total and the other formula columns stay as they are.

Create the web app (one time)

  1. Go to script.google.com, signed in with the account that can edit the Burn Down Record, and click New project.
  2. Press Ctrl+A and Delete to remove the starter myFunction code, so the editor is completely empty. Paste in all of BurnDown.gs and save. You don't need to edit the script.
  3. Click Deploy → New deployment. Click the gear icon, choose Web app, and set Execute as: Me and Who has access: Only myself. Click Deploy, then Authorize access. If you see "Google hasn't verified this app", click Advanced → Go to (project), then Allow.
  4. Copy the Web app URL, which ends in /exec. It's also under Deploy → Manage deployments. Open it once in Chrome. You should see {"ok":false,"error":"No sheet set…"}, which means the web app is working.

Connect the extension

  1. Click ⚙ and go to Burn Down sheet. Paste the Burn Down Record's address into Sheet link, and the /exec URL into Web app URL. Enter your Tab name exactly as it appears in the sheet. Click Save & test.
  2. For each customer, fill in Sheet customer name, Account #, CSP level, Allotted and Bucket. Billable time is blocked until the customer name, account number and CSP level are set.

If a sheet write fails, your Journeys entries are still saved, and the rows wait in a Retry now bar. Changing or deleting an existing billable entry doesn't change the sheet; update those rows by hand.

Changing the script later

Paste the new code and save. Then go to Deploy → Manage deployments → ✏ → Version: New version → Deploy. That keeps the same /exec URL, so nothing changes in the extension. A New deployment would create a new URL, which you'd have to paste into ⚙ again. Optional: set TOKEN in the script, redeploy, and enter the same value in the extension's Token field.

Troubleshooting

Not signed in to JourneysSign in at onboarding.nextiva.com, then try again.

Updating

Download the new zip, extract it, and copy its files over your existing journeys-time-entry folder. Keep the folder name so your boards and settings are kept. Then click the reload arrow on the extension in chrome://extensions. Full documentation is in README.html inside the folder.

Works in Google Chrome and Microsoft Edge. All settings stay in your own Chrome profile.
